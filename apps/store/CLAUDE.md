# apps/store

The customer site at `digital.vertexmedia.pro`: Next.js 16 (App Router, Turbopack, Cache Components), Arabic RTL, dark by default (ADR 0002, 0011, 0012). Read `brand/identity.md` (§6 is the store's own guidance) before visual work.

## Layout
- `src/app/`: routes, thin: data loading and layout. `layout.tsx` (html `lang="ar" dir="rtl"`, the `dark` class, the theme script, header and footer), `page.tsx` (the storefront), `games/[slug]/` (S09), the account routes (`sign-in/`, `sign-up/`, `verify-email/`, `forgot-password/`, `account/`), `wallet/`, `orders/`, `sitemap.ts`, `robots.ts`, `%5Finternal/revalidate/route.ts` (`POST /_internal/revalidate`: a folder starting with `_` is private in the App Router, so the `_` is written `%5F`), `not-found.tsx`, `error.tsx`, `globals.css` (Tailwind + `@vertex-digital/ui/styles.css`).
- `src/instrumentation.ts` (+ `instrumentation-node.ts`): copies only `API_INTERNAL_URL`, `STORE_URL` and `STORE_REVALIDATE_SECRET` from the root `.env` at server start (and `DATABASE_URL` outside production, to derive the secret as the worker does): the public store never holds the other apps' secrets; production refuses to start without the secret. `src/lib/server-env.ts` reads them (server code only), `src/lib/cache-tags.ts` names the cache tags.
- `src/features/<area>/`: components, server data functions and actions of one area. Pattern to copy: `src/features/auth/` (`requests.ts`: pure request functions with a unit test; the client forms that use them; field messages in `validation.ts`) and `src/features/account/` (a page read in the browser with the session cookie: skeleton, error and sign-in redirect); `src/features/wallet/` adds a cursor list with "load more" and the header balance chip; `src/features/notifications/` the live stream shared by a tab (`live.ts`: one `EventSource`, `useNotificationEvents` for the bell, the wallet and the deposit page) and toasts kept inside the card that uses them; `src/features/orders/` (S08) "طلباتي" as cards with "load more" and the order page with its codes masked until revealed (`revealCode`), stage texts in `stages.ts`; `src/features/deposits/` a dynamic `[id]` page (`useParams` inside `<Suspense>`, `notFound()` for another customer's record), a money form (`Idempotency-Key` per body, ALTCHA) and an image upload by paste, picker or camera. S09: `src/features/catalog/` the cached public pages (`data.ts`: `'use cache'` reads of the API's public routes with the `catalog` tag and a 5-minute life; `home-page.tsx` and `game-page.tsx` server components; `game-shop.tsx` the client part: packs, the lazy calculator and the buy box placement; `revalidation.ts` the internal route's check), `src/features/purchase/` the buy box (`buy-box.tsx`, loaded only once a pack is chosen: fields checked with the contracts' CT7 schema, the player check `player-check.ts`, the draft kept through a sign-in `draft.ts`, slide-to-pay, one `Idempotency-Key` per body), `src/features/search/` the `Ctrl+K` dialog (code and index loaded on the first open, recent searches in `localStorage` behind try/catch).
- `src/components/`: app-wide pieces (header, footer, theme switch, account link and menu, form alert). `src/lib/`: `i18n.ts` (`t()`), `theme.ts`, `api.ts` (`apiRequest`: same-origin calls that answer a code and the refusal's `details`, never throw; a `FormData` body goes as multipart), `errors.ts` (`errorText`), `altcha.ts` (proof of work in the browser), `safe-redirect.ts`, `format.ts` (dates, `ltr()` to keep `$25.00` whole in an Arabic sentence), `use-search-param.ts`.
- `src/messages/ar.json`: every UI string. `e2e/`: Playwright specs, `test.ts` (the API mock and screenshot helper).

## Rules
- Server components by default; `'use client'` only for interaction. A page must stay static or cached: never read cookies or the session in a server component of a public page; customer-specific parts load in the browser (as `AccountLink` does) until a feature's spec says otherwise.
- With Cache Components, anything time- or request-dependent sits inside `'use cache'` (tagged per entity once the catalog exists, ADR 0002) or a `<Suspense>` boundary; the build fails otherwise.
- Cached reads of the API (pattern: `src/features/catalog/data.ts`): a `'use cache'` function with `cacheTag` from `lib/cache-tags` and `cacheLife`, called from a server component inside `<Suspense>` after `await connection()`, so it runs at request time and never during the build (the API may be away then); the result is then served from the cache until the worker expires its tag. A failed read throws (never cached) and the route's error view offers a retry. Only public routes, no cookie: what a customer owns loads in the browser.
- Money formatting and the contracts' schemas (zod) stay out of a page's first load: render prices in server components and pass them to client components as `children` (`PackContent` into `PackButton`), and load heavy client parts with `next/dynamic` when they are first needed (the buy box, the calculator's body, the search dialog).
- Anything a field's blur changes must not move what sits under the pointer: the player check's status has a fixed slot, or the press on "متابعة" that blurred the field loses its click.
- UI from `@vertex-digital/ui` through its subpaths only (`@vertex-digital/ui/components/button`, `@vertex-digital/ui/brand/logo`), never the root barrel: the barrel puts every client component in the first load. Missing component: add it to `packages/ui`.
- Logical CSS only; `packages/ui/src/conventions.test.ts` checks this folder too. Touch targets at least 44 px (`size="xl"` buttons, `h-11` inputs); inputs use `text-md` so phones do not zoom.
- Text only through `t('<area>.<key>')`, Arabic copy per `brand/identity.md` §10 (no exclamation marks, every error says what to do next). Server errors show `errors.<code>` through `errorText()`, never the server's message. Fields for LTR values (email, password, IDs) set `dir="ltr"`.
- Account pages are static shells; everything about the customer loads in the browser with the session cookie and is never cached. No personal data in URLs: the address waiting for its code travels in session storage (`features/auth/pending-email.ts`).
- Image previews of local files use data URLs: the CSP allows `img-src 'self' data:`, not `blob:`.
- Read query parameters with `useSearchParam` (after hydration), not `useSearchParams`, so pages stay static without a Suspense boundary. Exception: inside a boundary a dynamic route already needs (the game page's `?pack=`, which a search result can change without a reload), `useSearchParams` follows the URL.
- The store's CSP allows inline scripts so pages stay cached (ADR 0015): `dangerouslySetInnerHTML` only for constant strings written in this repository (the theme script), never for data from the API or customers.
- API calls go to `/api/...` on the same origin (nginx in production, a rewrite to the API in development). Customer auth is Better Auth at `/api/auth`.
- Brand files are imported from `brand/` (`layout.tsx` icons), never copied into a `public/` folder.
- Performance budget (`e2e/store.spec.ts`): first load of `/` at most 210 KB of JS (200 until S05, 205 until S09: the whole Arabic catalog ships in it; measured 206 in S09 PR 3) and 20 KB of CSS, gzipped; the game page `/games/[slug]` at most 230 KB of JS and 20 KB of CSS (measured 223 and 9 in S09 PR 3, the buy box not chosen yet). Raising either needs a reason in the PR.

## Tests
- Unit: `src/**/*.test.ts` (Vitest), next to the code.
- E2E (`e2e/`): against the production build on port 4001; server components read the catalog from `e2e/catalog-server.mjs` (port 4002, fixed answers from `e2e/catalog-fixtures.json`; `e2e/catalog.ts` builds the search index and finds packs from the same data), and a second store on 4003 reads an empty catalog (`EMPTY_STORE_URL`, `e2e/servers.ts`); in the browser the API is mocked per test with `api.on('METHOD /path', status, body)` (`api.last(key)` reads what was sent; an empty wallet, an empty notification stream and every email choice on are answered by default, since the header reads the first two on every signed-in page; `api.stream(key, events, delayMs?)` answers server-sent events, after a delay when a test changes what the page reads next; catalog images answer a PNG by default), and a request without a mock fails the test, as do page and console errors. Next.js keeps the previous page mounted but hidden after a client navigation: find fields among the visible ones (`accounts.spec.ts`, `field()`). Every new screen adds RTL screenshots, dark and light, at phone width and desktop (the `phone` and `desktop` projects).

Run: `pnpm --filter @vertex-digital/store test` · `pnpm --filter @vertex-digital/store typecheck` · `pnpm test:e2e` (builds first) · dev: `pnpm dev` (port 3001, with the API on 3000).
