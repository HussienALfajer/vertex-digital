# apps/admin

The admin panel at `digital-admin.vertexmedia.pro`: React 19 + Vite SPA, TanStack Router and Query, i18next, Arabic RTL; follows the system theme with a remembered switch (ADR 0002, 0007, 0011, 0012). Read `brand/identity.md` before visual work.

## Layout
- `src/routes/`: TanStack Router file routes, thin: guard, then a page component. `_app.tsx` guards the shell (session, then the CLI-issued password changed, then TOTP enrolled: `setupStep()`) and holds the re-authentication provider; `login.tsx`, `change-password.tsx`, `setup-two-factor.tsx` sit outside it. `routeTree.gen.ts` is generated by the router plugin: never edit it.
- `src/features/<module>/`: one folder per API module: `<module>.queries.ts` (query options and mutations, when the first one arrives), page components, forms. `features/account/` holds sign-in, the TOTP and backup-code steps, the enrolment, the password change, the account page and the re-authentication dialog (`reauthentication.tsx`).
- `src/components/`: app-wide pieces (shell, auth layout, theme switch, form alert, confirm dialog, copy button). `src/lib/`: `api/client.ts` (`api`, `call()`, `ApiError`), `auth.ts` (`authClient`, `sessionQuery`, `useSession()`, `setupStep()`, `leaveSession()`), `session-events.ts` (idle expiry and pending password change, from any call, handled in `main.tsx`), `altcha.ts`, `errors.ts`, `format.ts` (dates, `formatSince`, `ltr()` to keep `$25.00` or `+5%` whole in an Arabic sentence), `idempotency.ts` (`useIdempotencyKey()`), `safe-redirect.ts`, `theme.ts`, `clipboard.ts`. `src/i18n/locales/ar.json`: every UI string.
- Pattern to copy for a form: `src/features/account/login-page.tsx` (React Hook Form + contract schema + `standardSchemaResolver`, errors through `errorMessage()` and `FormAlert`; a server error on a field is set with `type: 'server'`). For a list page: `src/features/audit/` (filters in the URL through `validateSearch`, cursor list with "load more", detail sheet). For a review page with a decision form: `src/features/deposits/`. For a page that waits on something outside the panel (polling in the background until it changes): `src/features/telegram/` (a single-use link with QR code and countdown). For a catalog-style editor (tabs in the URL, add/edit dialogs, move up / move down, archive filters, image uploads): `src/features/catalog/`. For rows selected across pages into an all-or-nothing dialog with refused rows shown in place, and a drawer editing a row's children: `src/features/suppliers/` (`offers-tab.tsx`, `import-dialog.tsx`, `routes-drawer.tsx`). For a decision list with a bulk action and a result per row: `src/features/pricing/reviews-page.tsx`. For a paged list with tabs and filters in the URL, and a detail page with a decision panel (one dialog per decision, re-authentication, the dialog's `Idempotency-Key`) and values revealed for 30 seconds: `src/features/orders/` (S08; the navigation badge reads `/api/admin/orders/counts` every minute). For a live screen over the admin stream (`lib/admin-stream.ts`: one `EventSource` per tab, `useAdminStream`, `useStreamState`, `useVisibleAgain`, `useDebounced`; reads sent as background requests), a board of cards with a ticking clock, a side sheet with the order's actions, and dialogs shared with the order page: `src/features/orders/` (S11: `live-page.tsx`, `live-sheet.tsx`, `order-actions.tsx`, `reroute-dialog.tsx`, `fulfil-dialog.tsx` with an image uploaded at once and previewed from the file); a home page of cards from one read: `src/features/dashboard/`. For a money action: `src/features/wallet/adjust-dialog.tsx` (an `Idempotency-Key` per attempt from `useIdempotencyKey()`, kept across re-authentication and retries, new once a field changed; the typed confirmation; refusals under their field). For a search page and a profile whose tabs each read their own route (S12): `src/features/customers/` (`customers-page.tsx` one search field and status tabs in the URL; `customer-page.tsx` an actions menu by status, tabs in the URL, `customer-sections.tsx` per-tab skeleton and retry; `customer-dialogs.tsx` reason dialogs that show a refusal's `details` (archive blockers) and dollar fields read with `parseUsd` into USD units; `customer-marks.tsx` the customer's chips, pinned note and signals beside a deposit, an order or a ticket). For a queue and a conversation with images (S12): `src/features/support/` (`support.queries.ts` multipart bodies with an `Idempotency-Key` and the `open` badge from the queue's own count; `image-picker.tsx` up to 3 images previewed as `data:` URLs, which the CSP allows, never `blob:`; `ticket-page.tsx` customer text as plain text, links never made clickable, Ctrl+Enter sends). For money moves between places with a typed amount in each place's precision, a dialog that changes with its two selects, and a status read again while a job runs (S13): `src/features/reconciliation/` (`movement-dialog.tsx`, `treasury-form.ts` refusals by field and the confirmation shown on the API's answer, `count-dialog.tsx` the books shown only after saving, `settings-sheet.tsx` a settings drawer with re-authentication). For report tables sorted on the client with a totals row and a file download: `src/features/reports/` (`report-table.tsx`, `report-search.ts` Damascus periods in the URL, `reports.queries.ts` the `.xlsx` read as a blob). For store content (S14): `src/features/content/` (`content-layout.tsx` tabs that are routes, `page-editor.tsx` a text editor with problems by line, a store-styled preview at two widths (`StorePreview` in `content-parts.tsx`), Ctrl+S, the stale-revision dialog, `useBlocker` on unsaved changes and the versions; `faq-page.tsx` cards reordered by buttons or native drag; `banner-dialog.tsx` an image dropped or picked with its refusals by reason, and Damascus `datetime-local` schedules through `damascus-time.ts`; `announcements-page.tsx` a switch that confirms the row it replaces).

## Rules
- UI from `@vertex-digital/ui` only; missing component: add it to `packages/ui`. Logical CSS only (`packages/ui/src/conventions.test.ts` checks this folder).
- Fields for LTR values (email, password, codes) set `dir="ltr"`. Icon-only buttons get an `aria-label` and a `Tooltip` with the same text.
- No hard-coded user-facing text: `t('<area>.<key>')`, keys type-checked. Server errors show their code's text through `errorMessage()` (API codes under `errors.api`, Better Auth codes under `errors.auth`), never the server's message.
- Admin mutations run through `useReauthentication()` (in their `<module>.queries.ts`) so a route the API marks sensitive opens the re-authentication dialog and is retried (rule D5); outside the shell (the forced password change) it runs the action as it is. Queries do not refetch on their own (window focus, reconnect): only what the admin does counts as activity for the 30-minute idle timeout (rule D4); polling (the deposits badge, the stale-rate banner) sends `BACKGROUND_REQUEST` (`X-Background-Request: 1`, `lib/api/client.ts`).
- Server state in TanStack Query; query keys start with the module name. API calls through `api` and `call()`, typed from `apps/api/openapi.json` (`src/lib/api/schema.gen.ts`, generated: never edit). After an API change: `pnpm --filter @vertex-digital/api openapi:export`, then `pnpm --filter @vertex-digital/admin api:generate` (CI fails when either is stale). Admin auth goes through `authClient` (`/api/admin/auth`).
- Forms validate with the schema from `@vertex-digital/contracts` the API uses.
- The panel's host serves only `/api/admin/*`, the ALTCHA challenge and the catalog image previews (`/api/catalog/images/*`, S06) (nginx): never call a customer route from here.
- Route files are eager (only their component is split off): what they import besides the page component (search parsers, tab lists) lives in a light module such as `<module>-search.ts`, never in a page module, which would pull the page and its dialogs into the entry. `vite.config.ts` bundles everything the entry imports statically into one `app` chunk.
- One admin, full access (ADR 0016): no permission checks in the UI; the API enforces access.
- The inline theme script in `index.html` has its hash in the CSP (`deploy/nginx/vertexdigital-admin-csp.conf`); `src/csp.test.ts` fails until both match.

## Tests
- Unit: `src/**/*.test.ts` (Vitest), next to the code.
- E2E (`e2e/`): against the production build (`vite preview`, port 4173). `e2e/test.ts` mocks the admin Better Auth instance and the API with a small state machine (`admin`), the catalog and pricing in `e2e/catalog-mock.ts` and the suppliers, routes, prices and reviews in `e2e/suppliers-mock.ts` (S07, on the contracts' pure rules; a test scripts the next sync with `admin.suppliers.script`), the orders in `e2e/orders-mock.ts` (S08, S11: the live board on `liveColumn`, route options, reroute, proof and fulfil), the customers and support tickets in `e2e/customers-mock.ts` (S12: state changes on the contracts' schemas, multipart ticket bodies read with `multipart()`, key replays), the home page in `e2e/dashboard-mock.ts`, the books, treasury and reports in `e2e/reconciliation-mock.ts` (S13: movements posted with the contracts' `treasuryPostings`, `seed()` for an open mismatch, `reports.<kind>` per test), the store content in `e2e/content-mock.ts` (S14: revisions, versions and the FAQ's publications on the contracts' `richTextProblems` and `bannerState`; `saveElsewhere` for a stale save, `nextUpload` for a banner refusal, `seed…` for the screenshots; uploaded images served by the catalog mock), and the admin stream through `admin.stream` (events, a delay, the `retry` the browser waits before reconnecting); a request it does not answer, or that `openapi.json` does not declare, fails the test, as do page and console errors. Every new screen adds RTL screenshots in both themes.

Run: `pnpm --filter @vertex-digital/admin test` · `pnpm --filter @vertex-digital/admin typecheck` · `pnpm test:e2e` (builds first) · dev: `pnpm dev` (port 5173, with the API on 3000; open `http://127.0.0.1:5173`, the `ADMIN_URL` the API accepts).
