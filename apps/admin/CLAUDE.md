# apps/admin

The staff panel at `digital-admin.vertexmedia.pro`: React 19 + Vite SPA, TanStack Router and Query, i18next, Arabic RTL; follows the system theme with a remembered switch (ADR 0002, 0007, 0011, 0012). Read `brand/identity.md` before visual work.

## Layout
- `src/routes/`: TanStack Router file routes, thin: guard, then a page component. `_app.tsx` guards the shell (session, then TOTP enrolled); `login.tsx`, `setup-two-factor.tsx` sit outside it. `routeTree.gen.ts` is generated by the router plugin: never edit it.
- `src/features/<module>/`: one folder per API module: `<module>.queries.ts` (query options and mutations, when the first one arrives), page components, forms. `features/account/` holds sign-in, the TOTP and backup-code steps and the enrolment.
- `src/components/`: app-wide pieces (shell, auth layout, theme switch, form alert, confirm dialog). `src/lib/`: `api/client.ts` (`api`, `call()`, `ApiError`), `auth.ts` (`authClient`, `sessionQuery`, `useSession()`, `leaveSession()`), `altcha.ts`, `errors.ts`, `safe-redirect.ts`, `theme.ts`, `clipboard.ts`. `src/i18n/locales/ar.json`: every UI string.
- Pattern to copy for a form: `src/features/account/login-page.tsx` (React Hook Form + contract schema + `standardSchemaResolver`, errors through `errorMessage()` and `FormAlert`).

## Rules
- UI from `@vertex-digital/ui` only; missing component: add it to `packages/ui`. Logical CSS only (`packages/ui/src/conventions.test.ts` checks this folder).
- Fields for LTR values (email, password, codes) set `dir="ltr"`. Icon-only buttons get an `aria-label` and a `Tooltip` with the same text.
- No hard-coded user-facing text: `t('<area>.<key>')`, keys type-checked. Server errors show `errors.<code>` (Better Auth codes under `errors.auth`), never the server's message.
- Server state in TanStack Query; query keys start with the module name. API calls through `api` and `call()`, typed from `apps/api/openapi.json` (`src/lib/api/schema.gen.ts`, generated: never edit). After an API change: `pnpm --filter @vertex-digital/api openapi:export`, then `pnpm --filter @vertex-digital/admin api:generate` (CI fails when either is stale). Staff auth goes through `authClient` (`/api/admin/auth`).
- Forms validate with the schema from `@vertex-digital/contracts` the API uses.
- The panel's host serves only `/api/admin/*` and the ALTCHA challenge (nginx): never call a customer route from here.
- Permission checks in the UI only hide things; the API enforces them.
- The inline theme script in `index.html` has its hash in the CSP (`deploy/nginx/vertexdigital-admin-csp.conf`); `src/csp.test.ts` fails until both match.

## Tests
- Unit: `src/**/*.test.ts` (Vitest), next to the code.
- E2E (`e2e/`): against the production build (`vite preview`, port 4173). `e2e/test.ts` mocks the staff Better Auth instance and the API with a small state machine (`staff`); a request it does not answer, or that `openapi.json` does not declare, fails the test, as do page and console errors. Every new screen adds RTL screenshots in both themes.

Run: `pnpm --filter @vertex-digital/admin test` · `pnpm --filter @vertex-digital/admin typecheck` · `pnpm test:e2e` (builds first) · dev: `pnpm dev` (port 5173, with the API on 3000; open `http://127.0.0.1:5173`, the `ADMIN_URL` the API accepts).
