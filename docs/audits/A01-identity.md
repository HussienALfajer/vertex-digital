## Summary
31 findings: no P0 or P1, 16 P2, 15 P3. All fixed but one P3 deferred. By dimension: security 8 (four on the edge and in the API's limits, four in the clients' sign-out and redirects), frontend and states 11, UI and accessibility 6, tests 4, spec conformance 2. The authentication core held up: access on every route, owner filters, enumeration-proof answers, decoy codes, one `INVALID_OTP`, session checks inside every account change, the admin's idle and absolute rules, audit in the same transaction.

What changed:
- **Server:** ended sessions and expired verification rows of both instances are deleted hourly by `auth.purge-expired`. The admin's password and re-authentication checks are limited per admin (10 in 15 minutes, any address). The per-email sign-in failure counter is bounded. nginx's auth zone covers the passkey routes and the passkey grant.
- **Customer:** every sign-out of this browser forgets the push subscription, the cart and the hints, the account entry pages send a signed-in customer on, `/account/email` checks the session first, `/forgot-password` keeps `?next=` and offers a new code after a minute, a new password equal to the email is refused in the card, the email choices say when they could not load and their switches have 44 px targets, closed registration shows no terms.
- **Admin:** a sign-out leaves only once the server confirms it, an ended session met in the re-authentication dialog goes to sign-in with the idle notice, regenerated backup codes are guarded against leaving, both code screens offer download, a password equal to the email is refused, the one-time password dialog closes only through its button, a failed session read after the code offers a retry, sign-out clears the mutation cache.

### Known leads
All eight leads of `docs/audits/README.md` were confirmed, and five of them were also seen in the live test: A01-6 (sessions card sign-out), A01-13 (auth pages do not redirect), A01-7 (`/account/email` session check), A01-10 (no resend on `/forgot-password`), A01-8 (password card equals email), A01-9 (preferences card hidden), A01-20 (setup page sign-out without `leaveSession()`), A01-14 (terms while registration is closed).

### Checked and clean
- Access: every route of the group declares its access; customer routes refuse admin sessions and the reverse; a customer's sessions and passkeys are filtered by owner (another's answers 404); the test-customer reset refuses real customers; `@Sensitive()` on the test-customer routes.
- Enumeration and codes: identical answers for sign-up, code requests, reset and email change; decoy codes; one `INVALID_OTP` for every failed check; 5 tries a code; codes hashed and bound to the email change's new address; send limits in PostgreSQL.
- Sessions: archived customers get no session and lose theirs at once (`customers/state.ts:212`); password and email changes lock the customer and re-check the session; passkey sessions go through the same hooks; admin idle and 12-hour rules on Nest and Better Auth routes; TOTP enrolment ends password-only sessions; no trusted devices; the TOTP sign-in step limited to 5 tries by Better Auth.
- Audit and emails: every S01 and S22 action audited in its transaction; outbox rows in the same transaction; code params cleared after send (seen live: the outbox row's code was null once sent) and by `email.purge-codes`; SMTP errors reported without the server's text.
- CLI: one admin (advisory lock and single-row index), passwords printed once, never logged; runs audited.
- RTL, i18n and digits: no physical CSS classes, no hard-coded strings, arrows flip, LTR fields set `dir="ltr"`, Latin digits in dates and addresses, confirmations on "sign out everywhere", passkey removal and test-customer reset.
- The live test's "SY" textbox on `/sign-up` is Base UI's hidden form input of the country select; the select itself is labelled "رمز الدولة". Dropped.
