## Summary
39 findings: no P0, 1 P1, 16 P2, 22 P3. 32 fixed, 4 moved to A10 (panel- and repo-wide patterns: hard-coded separators, dialogs that close on Escape, the OpenAPI request types), 3 P3 deferred (below). The one P1 was data, not code: PUBG Mobile's subscription and offer packs carried an in-game amount, so the calculator sold "Prime" as UC; the owner chose to clear those amounts. The catalog core held up: one access decorator per route, no supplier or cost data in public answers, hidden and paused items filtered, buying a hidden pack or at a tampered price refused, audit in every write's transaction, sound lock order.

What changed:
- **Customer:** the calculator, the per-100 price and the amount search commands read UC only on PUBG Mobile; the error page's retry really reads the page again; the search dialog retries a failed index, keeps the focus in its field and has a 44 px clear button; a search command on the game page it names applies the saved ID; a refused undo of a hidden quick-buy card says so; the calculator's result is announced.
- **Admin:** the game form keeps what was typed across tabs and asks before leaving it; saving an active game without a cover says so under the cover; the categories reads (form, dialog, linked supplier categories) load and retry; an image of the wrong type or size is refused before upload; a search term typed without Enter is kept; Save waits for a supplier cover; the reorder buttons wait for the category's own games; quick links name the pack they are filtered to.
- **Backend:** a pack's maximum quantity edit reprices it at once; an out-of-stock refusal refreshes the store; the public whole-catalog reads have an nginx zone of their own; the game page reads one game's row.

## Owner decisions
- A03-1 (2026-10-27): fix the data, not the model. The in-game amount stays one field meaning the game's main currency; packs in another unit (subscriptions, passes, offers, a second currency) leave it empty. The production change is a single audited transaction (one `catalog_product.updated` entry per pack, actor `cli`) run after the deploy. No question added to `docs/open-questions.md`.

## Deferred
- A03-34 (P3): unknown slugs cached as `null`. The cache is bounded and evicts the oldest entries; a random-slug scan costs one cheap API read per slug (no routing state for an unknown game, A03-37) and goes through nginx's general zone. A shorter life for a miss needs Next's `cacheLife` inside a branch, which the installed docs could not be read to confirm; revisit in A10 with the store's caching.
- A03-36 (P3): a database guard for "archive, never delete" and immutable slugs on the catalog tables. The API and worker test suites and `db:seed-local` delete catalog rows as the app role; revoking `DELETE` needs those moved to the owner role first, a platform change. Recorded for A10.
- A03-39 (P3): the quick-buy slot's reserved height for a signed-in customer with no cards. A fix needs a second device hint set before paint (a change to the session hint script, ADR 0015); recorded for A10 with the store's hints.
- For A05 (recorded in the README): the supplier import sets `game_amount` from pack names, which is how subscriptions and offers got one (A03-1).
