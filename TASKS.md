## PR 2 — Money core: contracts and db (`feat/money-core`) · Opus 5.5 `xhigh`
- [x] `packages/contracts` package: Zod 4, built to `dist/` with `tsc`, `CLAUDE.md`; Vitest with 100% coverage thresholds (`@vitest/coverage-v8`), so "100% unit-tested" (ADR 0011) is a check, not a promise
- [x] `src/money.ts` (ADR 0003): `CURRENCIES` (`USD`, `SYP`), `CURRENCY_SCALE` (USD 1,000,000 micro-dollar units, SYP 100), `USD_CENT` (10,000 units); schemas for an amount in units (non-negative safe integer) and a customer-facing USD amount (whole cents); `exchangeRateSchema` (SYP per 1 USD, exact decimal string, > 0, up to 4 decimals); exact USD↔SYP conversion with an explicit rounding direction (`up` / `down`, BigInt inside, never floats); `ceilToStep`; `sypDisplayPrice` (USD × rate rounded up to the SYP step). The deposit credit rule (SYP received → whole-cent USD credit) is left to the F05 spec
- [x] `src/wallet.ts` (the `wallet` module owns the ledger, ADR 0011): account kinds (customer wallet, Sham Cash receipts, USDT receipts, supplier prepaid, sales revenue, cost of goods, refunds, adjustments) and journal kinds (deposit, purchase, refund, cost of goods, adjustment) as `as const` lists that the database enums reuse
- [x] `src/orders.ts` (ADR 0004): order statuses, the transition table, terminal statuses, `canTransitionOrder`; the test covers all 81 status pairs. Owner approved (2026-10-06): `paid → refunded` when no profitable route is left as the worker routes a paid order (A03/A04), recorded in ADR 0013
- [x] `src/errors.ts`: `ERROR_CODES` with the codes this PR uses (`INSUFFICIENT_BALANCE`, `IDEMPOTENCY_KEY_REUSED`); other codes arrive with their features, the error response shape with the API (PR 3)
- [x] `packages/db` package: Drizzle on node-postgres, `createDatabase`, root `.env` loader, UUIDv7 `newId()`, `schema/columns.ts` (`id`, `timestamps`, `archivedAt`, `amountUnits`, the `currency` enum), `runMigrations` as the owner role under an advisory lock, migrate CLI (`dist/cli/migrate.js`, for deploys), `drizzle.config.ts`, Vitest global setup that migrates the test database, `CLAUDE.md`
- [x] Ledger schema (ADR 0003), generated migration `0000_ledger`: `ledger_accounts` (kind, currency, unique `code`; a customer wallet is USD only, by a check), `ledger_journals` (kind, unique `idempotency_key`, `posting_count` ≥ 2, `created_at`; no `updated_at`/`archived_at`), `ledger_postings` (journal, account, currency, `amount_units` bigint ≠ 0; a composite foreign key makes the posting's currency match its account's). A posting adds its amount to its account; a balance is the sum. The wallet's link to the customer arrives with F01/F03, when the customers table exists
- [x] Custom migration `0001_ledger_guards`: a trigger refuses `UPDATE`, `DELETE` and `TRUNCATE` on journals and postings; `REVOKE UPDATE, DELETE, TRUNCATE` on them (and `DELETE, TRUNCATE` on accounts) from `PUBLIC` and every role but the owner, i.e. the app role (ADR 0014); a deferred constraint trigger checks at commit that every journal has exactly its declared postings (none added later) and sums to zero per currency, reading `public.` tables under a pinned `search_path`; the database stamps `created_at`; a trigger refuses changing an account's kind, currency or code
- [x] `src/ledger/`: `postJournal(tx, { idempotencyKey, kind, postings })`, inside the caller's transaction: validates (two or more non-zero safe-integer postings, known accounts, balanced per currency, wallet postings in whole cents), claims the key (`ON CONFLICT DO NOTHING`), returns the first journal for a repeated key and refuses a repeated key with different content (`IDEMPOTENCY_KEY_REUSED`), locks debited wallets in id order (`FOR UPDATE`) and refuses a negative balance (`INSUFFICIENT_BALANCE`); `accountBalance`; `LedgerError` carrying a contract error code
- [x] Tests: `conventions.test.ts` (UUIDv7 keys, business columns, timestamptz, no floats, indexed foreign keys, `*_units` columns are bigint, `idempotency_key` columns unique); guards (the app role owns nothing and lacks the privileges, cannot disable the trigger or grant itself; the trigger refuses the owner too, truncate included; no temporary tables for the app role; postings added later, even balanced, and a temporary table shadowing `ledger_postings` are refused; `created_at` cannot be backdated; unbalanced, single-posting and empty journals refused at commit, currency mismatch refused, account identity frozen); posting (balance, whole cents, repeated key, reused key); concurrency (parallel debits on one wallet never overdraw it, the same key posted in parallel posts once). Ledger rows written by tests stay in the test database (append-only by design); every run uses unique keys and accounts
- [x] ADR 0014, owner approved (2026-10-07): an owner role runs the migrations, the app role owns nothing (a single role cannot revoke `UPDATE` on a table other tables reference, and could disable its own triggers). `DATABASE_OWNER_URL`, `TEST_DATABASE_OWNER_URL`; `setup-local-db.mjs` creates both roles with default privileges, hands what the app role owned to the owner, and adds keys missing from an existing `.env`; `CONNECT` and `TEMPORARY` revoked from `PUBLIC`
- [x] Root scripts `db:generate`, `db:migrate`; `allowBuilds`: esbuild's install script stays blocked (its binary is an optional dependency)
- [x] CI: PostgreSQL 17 service; `scripts/setup-local-db.mjs` creates the owner and app roles, neither a superuser (a superuser would bypass the privileges under test); "Migrations match the schema" step inside the required `Typecheck, lint, test, build` job, so branch protection needs no change; the cloud session migrates the dev database; README getting started
- [x] Docs: commands table in `AGENTS.md`, `docs/workflow.md` (cloud session), `docs/ROADMAP.md`; ADR 0013 (`paid → refunded`, amends ADR 0004)
- [x] Checks (lint, typecheck, test, build, drift), reviewer, PR with auto-merge
